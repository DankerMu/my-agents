# 交互式视觉共创：自适应提问、视觉方案与约束锁定

> 本文件是 Skill 的**交互协议**，不要求额外程序、表单、持久化数据库或生图 API。依靠当前会话上下文执行；跨会话可让用户复制「视觉方案摘要」继续。只在触发引导、确认或迭代时按需读取。

## 1. 目标与底线

核心目标不是让提示词更长，而是通过**最少、最有信息量的交流**减少错误的视觉决策。

1. 用户负责决定「画什么／偏爱什么／必须保留什么」；Agent 负责说明专业视觉选项及其**可感知的画面差异**。
2. 用户不必知道艺术术语。先用通俗说法，必要时在括号中标注术语：如「轮廓清楚、色块利落（日系赛璐璐）」。
3. 交互是**为理解服务**，而不是完成仪式。材料足够或用户要直接出稿时不要再问。
4. 不能把 Agent 的推测、默认值或例子变成「用户已确定」的创作条件。
5. 不能改写已确认的主体、文字、数量、角色一致性或指定位置来追求审美。
6. 禁止无休止确认：一旦解决高影响分歧，就要推进出稿。

## 2. 每轮判定：直接出稿、提问、还是方案确认

把每个缺项按**对成图结果的影响**分类，而非按字段是否填写分类。

| 层级 | 例子 | 一般行动 |
| --- | --- | --- |
| P0 冲突／不可进行 | 用户既要保留原图人物又要完全重画其脸；用户要求精确科研数据图却没提供数据；多张参考图职责相冲突 | 先指出冲突，问**一个**可做决定的问题；无法精确时给可靠替代方案 |
| P1 主视觉方向 | 未知是图标还是摄影；要“高级”但不知道是极简、奢华还是纪实；不知道主体究竟是什么 | 优先问一个高价值问题，列出两三条明确选项 |
| P2 布局／用途关键项 | 人物特写还是环境全景；PPT 需否留文字区；参考图以哪张为身份锚 | 若能大幅改善结果则问，若用户授权 Agent 自行决定则给明确建议 |
| P3 修饰细节 | 灯笼数量、点缀花纹、无指定的微小背景材质、镜头型号 | 通常自行保守补全，**不要为此打断用户** |

**直接模式优先级**：用户明确说「只要最终 prompt、不要提问、你来决定、直接出图」，立即完成；即便有高影响不确定项，也选保守方案，仅在不可能满足硬约束时做必要澄清。用户没有说不准提问且画面核心决策不明时才引导。

**判定实例**：
- 「一张米白墨绿的极简读书 App 插画，不要字」——方向已够清晰，直接输出。
- 「做一张高级一点的宣传图」——先问宣传对象或目标，而不是瞎设人物、摄影、美妆。
- 「帮我选摄影风格」——先给三种直观方案并说明适用效果，再让用户选或委托 Agent 选。
- 「我的角色双马尾、红围巾、橘色羽绒服、糖葫芦、雪夜庙会、16:9、赛璐璐」——信息已很足，不必重新做选项问卷。

## 3. 如何设计真正有用的问题

### 3.1 单轮问题预算

- **默认 1 个关键问题**。只有两三个独立问题一起回答更省事时，才一次问 2–3 个。不要以固定 3 题作为每次开始的模板。
- 每个问题给 **2–3 个可辨别的选项**：描述具体成图差异、适合用途或利弊；另允许「自定义」「不确定，你推荐」。
- 不是所有问题都需要选项，例如「海报上必须出现的原文字是什么？」直接问更精确。
- 不问「你喜欢什么风格／更好看的感觉是什么」这种无法为普通用户提供新知识的开放问题；应翻译为有画面结果的选择。
- 不问已出现过的画幅、人物服装、参考图角色等；记录已有答案。

### 3.2 专业选项翻译法

把每个建议写成：**通俗视觉结果 →（专业术语）→ 实际影响**。示例：

| 用户模糊词 | 选项 A | 选项 B | 选项 C |
| --- | --- | --- | --- |
| 日系动漫 | 清晰轮廓、大片纯色阴影（赛璐璐），明快利落 | 柔和笔触与丰富光影（日系厚涂），细腻温暖 | 环境层次丰富、叙事感强（动画电影美术），氛围优先 |
| 真实摄影 | 自然光、生活痕迹（纪实），不摆拍 | 控光讲究、产品突出（商业摄影），干净精致 | 强冷暖层次、叙事与气氛（电影静帧），更戏剧化 |
| 国风 | 留白与墨色层次（水墨），写意克制 | 细线、分色与装饰纹样（工笔设色），精致规整 | 木版纹理和套色颗粒（传统版画），图形感鲜明 |
| 高级感 | 留白和少量颜色（极简），清爽 | 突出真实材质与尺度（材质导向），可信 | 大胆排版和色块（编辑设计），视觉冲击更强 |
| 科研报告 | 清晰层次、全图可读（严谨示意） | 强调真实地物外观（写实场景） | 流程和因果关系（分解剖视／流程示意） |
| 角色在画面中 | 脸部特写：突出表情 | 中景：人物和道具兼顾 | 远景：交代环境和叙事 |

不要固定给某一风格的选项表；根据用户主题、用途和已确认边界筛选。

### 3.3 第一轮回答模板（可变）

> 我理解你要画的是「[已知的主题、用途与硬约束]」。为了避免成图方向跑偏，先决定 **[一个高影响问题]**：
> - **A [直观结果]**：……
> - **B [直观结果]**：……
> - **C [可选]**：……
> 也可以告诉我自己的想法，或者说「你推荐」。

关键是提供**真实的选择能力**，而不是句式一致。用户选定一项后先整合，再判断是否仍有 P0/P1/P2 缺口；没有就生成。

## 4. 视觉方案（Visual Brief）的最小状态模型

会话里内隐维护下列字段，仅在复杂创作／用户需要确认／跨会话移交时简洁展示：

```yaml
visual_brief:
  task: "T2I / I2I / 风格迁移 / 科研示意等"
  purpose: "PPT、头像、海报、插画等；未知可留空"
  subject: "主体、数量、动作、关系"
  scene: "地点类型、时间、气候、背景"
  composition: "视角、景别、布局、留白"
  style: "主风格、次要局部工艺"
  lighting_palette: "主光、冷暖、配色"
  text: "必须原样保留的画中文字"
  references: "image1/2/3 各自承担什么功能"
  format: "画幅/透明要求"
  must_keep: "硬约束与已确认且不得变更的项"
  proposals: "Agent 建议但用户尚未确认的项"
  open_items: "尚待决定的高影响问题；没有则为空"
  revision: "v1 → v2 的精确变化"
```

**不要强迫用户填写 YAML**，这只是 Agent 内部的思维结构。对用户可只展示：

> **当前画面方案**：橙发猫娘，庙会糖画摊前，人物与街市兼顾；日系赛璐璐，灯火暖色对比蓝色雪夜，16:9。  
> **保持不变**：虎斑猫耳、橙白尾巴、糖葫芦、红围巾上的白猫、左上「福」字。  
> **待确认**：要突出角色表情，还是更突出龙舞与街市？

### 4.1 状态分级（防止“随便写”）

- **U 用户明示**：用户明确说出的内容。必须保留，除非用户后续更改。
- **L 用户锁定**：用户说「固定、不要改、保留原样、确定用这版」或确认完整视觉方案。之后只在明确变更时允许修改。
- **P Agent 提议**：为了帮助用户选择而建议的风格、色彩、布局；未被采纳前不能写成用户要求。
- **D 默认假设**：为让 prompt 可执行而保守补全的小细节；不可覆盖 U/L。需要时可以说明一次，不得以「你之前确定」称呼。
- **X 待决冲突**：会使结果截然不同、且用户偏好未知的问题；先解决或在直接模式下说明选择。

用户说「我选 B」 → 对应项升级为 **U**；用户说「B 固定，后面别改」 → 升级为 **L**；用户说「试试 B 也许」 → 临时方向，仍可调整。对已锁定的条件提出新修改，按最新**明确**指令更新该项，不将原项死锁。

## 5. 复杂任务的多轮共创

可按**阶段**组织，但不是每次都强制经过四轮：

1. **定目标**：确认图的用途、主对象以及任何精确文本、科学数据可靠性或身份保真要求。
2. **定视觉路线**：在必要时选择主风格、主体与背景的权重、画面情绪；可给两套简短视觉方向对照，但**先不要生成两份冗长 prompt**。
3. **定关键表现**：只就构图、光照、颜色或细节中的**最大不确定项**询问；其余由 Agent 专业补齐并标为建议。
4. **方案汇总**：复杂任务用 3–6 行复述用户已决定的内容和建议；若还存在重大分歧，询问确认；否则直接产出最终 prompt。
5. **迭代优化**：用户反馈后仅修指定部分；如出现新约束，明确它取代的旧约束。

**退出规则**：完成核心选择、用户说「就这样」「按这个出」「别再问」或已有充分信息时，不再追问。用户也可以主动要求「先看看方向」「继续完善」，这时不要抢着结束对话。

## 6. 修改与反馈：差异优先

收到反馈时先解析：

| 标签 | 含义 | 例子 |
| --- | --- | --- |
| KEEP | 要保留的条件 | 人物脸、服装、构图比例 |
| CHANGE | 明确要调整的方面 | 背景太抢眼 → 降低对比与细节密度 |
| ADD | 新要求 | 右上角增加一盏灯笼 |
| REMOVE | 删除项 | 不要额外的文字牌匾 |
| OPEN | 需要用户取舍的项 | 气氛更严肃，但不清楚是否允许降低饱和度 |

每轮只改 **1–3 个相关维度**；保留所有成功的内容。用户有生成图时应先基于图片指出可观察偏差；只有文字反馈时不要声称已经看见问题。若同一症状连续两次仍无法解决，不要继续堆词；考虑局部编辑遮罩、重绑参考图、控制分辨率/随机种子、分图合成等非提示词原因。

**反馈示例**：

- 「人物太大，其他都好」→ CHANGE 仅景别/人物占比；KEEP 角色外观、配色、风格、道具和背景；无需重新问风格。
- 「太像 AI 图」→ 反馈过于宽泛，先说明常见视觉成因并问是「塑料质感／假光晕／构图摆拍」中哪一种；若用户让你决定，可先做最小化降光晕、降过度锐化建议。
- 「蓝色太多，氛围还是热闹」→ CHANGE 仅冷暖面积比例；KEEP 题材、角色、热闹感、灯笼和节日语义。
- 「福字写错了」→ CHANGE 文字清晰度／单字位置；KEEP 其他内容；同时说明模型写字仍可能不稳，必要时后期叠字。
- 「图1的人脸还是不像」→ 锁定图1为身份锚；减少对脸的重述，推荐局部遮罩；不虚构身份特征。

## 7. 完成时如何交付

- **共创仍在进行**：只发一个关键问题和可选路线；必要时短视觉方案。不要输出「最终提示词」冒充已达成共识。
- **方案已定**：默认输出一个可复制的完整 prompt，加简短「画幅／任务类型」设置。用户要多方案才给多份。
- **用户明确只要 prompt**：只输出 prompt 正文；不附问句、方案状态、解析或围栏。
- **图像编辑**：沿用最小编辑策略，保留项不必长篇复述；不要把 T2I 的完整人像重绘描述直接用于 I2I。
- **复杂项目需交接**：可附 5–10 行「可复制视觉方案摘要」，区分已确定与 Agent 建议，作为跨会话上下文。

## 8. 禁止的交互反模式

- 每轮都问画风／构图／色彩三个固定问题。
- 用户给了 500 字细节还问「你要什么风格」。
- 把十种术语列成词典，要求普通用户自行查专业定义。
- 将用户没有选择的推荐项偷偷加入硬约束。
- 用户只要调整光线，却重新设计服装或镜头。
- 在完成每个小决定后机械地再说「是否确认？」
- 在没有生成图的情况下断言「这张图就是脸崩了」。
- 用「大师级、8K、电影感、惊艳」替代具体的可观察画面决策。
