# 参考图融合、局部编辑与失败图修复

## A. 输入与参考图锚点

首先弄清每张参考图的作用，而不是让模型“尽量参考这些图”：

| 角色 | 定义 | 典型话术 |
| --- | --- | --- |
| 内容锚点 | 主体身份、构造、姿态、核心道具 | `Preserve the subject's identity and proportions from <image1>.` |
| 风格锚点 | 颜色、线条、光影、绘画技法 | `Use the drawing medium and line quality of <image2> only, not its characters or background.` |
| 服装/物件锚点 | 衣服款式、纹样、产品外形 | `Use the coat design from <image3> while retaining the face from <image1>.` |
| 画布/构图锚点 | 背景布局、相机视角、场景几何 | `Keep <image2>'s framing and background layout.` |

同一参考图可以承担多个功能，但应写出**哪些继承、哪些不继承**。多参考图合成时，必须指定决定**画幅的底图**。如果用户说“图1的人物移到图2的室内”，图2通常是场景画布；如果“只给图1人物换衣”，图1通常是画布。

不可凭空描述不可见的参考图片。没有图时只给抽象绑定规则，不说“这张图脸朝左/衣服蓝色”。

## B. 最小编辑法

`Replace the striped scarf on the central character in <image1> with a thick red knitted scarf. Keep her face, hair, posture, other clothing and the entire background unchanged. Match existing shadows.`

**不推荐**：重述原图全部人物五官、背景古镇、所有灯笼、地面雪花、猫耳位置再加一句“把围巾换成红色”。这会让模型重新生成而不是真正局部编辑。

在修改中有两个相反目标时，先定边界：

- **保留原人物但换地点**：锁定脸、发型、体型和识别性配件，允许光源/环境色随新地点变化。
- **只换衣但其他不动**：锁定脸、姿势、画幅、背景，替换衣服的可见局部，不改变手部。
- **风格迁移但内容不动**：锁定人物数量、姿态、布局、物体类别和文本；只换绘画媒介、边缘质量、阴影组织。
- **重绘成高分辨率新图**：不宣称“扩大原图即可新增真细节”；要求在新渲染里维持布局和重要细节。

## C. 失败类型 → 针对性修正

按用户反馈或可见结果诊断，只改与故障相关的 1–3 个变量：

| 失败表象 | 可能的 prompt 问题 | 首选修正 |
| --- | --- | --- |
| 主体太小、被背景淹没 | 焦点不明确、背景要素过多 | `main subject occupies most of the central frame`; 减少背景竞争元素 |
| 想要的道具没出现 | 多个道具平铺列举、关系不清 | 把重要道具放进主体动作句：`holding a single tanghulu skewer visibly in the right hand` |
| 人物五官、脸或画风变了 | 编辑 prompt 重画了脸；参考图职责不明 | 简化修改为目标局部；`preserve facial identity from <image1>` |
| 人物多手、多尾、多耳 | 遮挡结构复杂、同时要求高动态姿势 | 明确数量和接触关系；减少手与身体交叠；选择清晰姿势 |
| 左右位置颠倒 | 只说“旁边”，没定位 | `on the viewer's left/right`; 对依赖人体左右的要求明确视角 |
| 内容被随意加上文字 | 未指定无文字却使用“poster/UI”等触发词 | 说明 `no visible text or labels in the scene`（当用户确实不希望有字） |
| “福”等中文写错 | 多文字并列、文字太小或没有强调精确字串 | 缩减到**单一可读字**、位置、对比度、方向；多字后期排版 |
| 色彩过艳/荧光感严重 | 关键词堆叠 vibrant、neon、cinematic | 明确实际配色和局部光源，降低全局发光/饱和 |
| 图像过于 AI 塑料感 | “ultra glossy、hyper detailed”等空洞词 | 具体 matte 布料、合理阴影、自然小瑕疵、真实环境光 |
| 动漫画风不稳定 | 同时出现摄影/PBR/动漫/油画 | 统一主媒介，仅保留 1–2 个局部技法 |
| 前景抢戏 | 过度细化小道具 | 明确道具较小、服务于场景，主体仍为最高对比焦点 |
| 古建筑/工程结构变形 | 视角、几何、工艺结构定义不足 | 采用正交/三分之四视角，明确对称和结构关系；高精度应使用 CAD/参考图 |
| 信息图数据胡编 | 把空白数据交给图像生成模型 | 生成不带数字的概念底图，数据和标签由后期叠加 |
| 修改一处导致别处改变 | prompt 长篇重描整个场景 | 仅描述变化区域，其他保留一句；必要时用局部遮罩 |
| 宽画幅画成方图 | 仅靠 prompt 指定 16:9 | 检查前端输出宽高参数或模型支持的尺寸 |
| 要透明却有白底/棋盘底 | 只说“无背景”或导出丢失 alpha | 明确 RGBA/alpha；检查文件格式和后处理流程 |

**归因谨慎**：图像失败未必来自 prompt，也可能是模型极限、推理设置、微调模型、参考图质量、节点连接、尺寸或随机性。不要承诺“把一句词加进去就一定修好”。

## D. 与多轮视觉方案联动

把上一轮**已确认和锁定的视觉方案**视为修订基线。收到反馈后先标出 `KEEP / CHANGE / ADD / REMOVE / OPEN`，**只修改 CHANGE／ADD／REMOVE 相关的提示词片段**。如果用户仅说「不好看」等不充分反馈，优先问一个能区分成因的直观问题；若用户授权直接决定，就给保守的局部修订。

- 用户说「主体太大，其他都好」 → 改景别／主体在画面中的占比，角色设定、颜色、光源、背景主题保持原样。
- 用户说「不像之前的脸」 → 将人物身份或参考图锚点升为锁定条件，不主动新增或替换面部特征。
- 用户说「之前定好的赛璐璐不能改」 → 保持主媒介，只在颜色／构图等请求维度修改。
- 用户说「我改主意了，改成厚涂」 → 这是新的明确指令，更新原有风格约束，不受旧版本阻拦。

详细的会话状态和用户提问规则见 [interactive-design.md](interactive-design.md)。

## E. 迭代规则

1. 如果有输出图，先描述**可观察事实**：“围巾样式变了，但脸部轮廓也发生改变”；不要编造未观察到的局部。
2. 归纳用户真正不满的 1–3 项，并从硬约束中确认不能动的内容。
3. 生成一条修订 prompt；**只动最少的词句**，保留已成功的对象与构图。
4. 如果原因不确定，可做 A/B：A 修正构图，B 修正风格（同 seed、同参数）；不要同时动十个因素。
5. 如果连续失败两轮，建议更改*工作流*而非无限堆词：参考图、遮罩局部编辑、拆图合成、分图生成、人工排字或选择适合的生成模型。

## F. 用户表达 → 可观察差异

- “不够可爱” → 可微调表情、眼睛、肢体语言和比例；不要未经允许变成幼儿形象。
- “人不像我了” → 优先锁定参考脸，减少面部改写，警惕手工贴脸拼接与风格不统一。
- “不够严肃” → 克制过饱和、科幻 HUD、镜头光晕和浮夸装饰，增强材料和环境可信度。
- “不够生动” → 添加符合物理的动作方向、姿态和视线互动，而不是无故增加元素数量。
- “像九宫格裁出来放大的” → 不建议再次双线性放大；要求**单张重新生成**且提供真实目标尺寸/比例。
